# Four-minute ThinkFlow demo

| Time | Show | Say |
| --- | --- | --- |
| 0:00–0:40 | Home, brand and Quick Start | “ThinkFlow is my customization of Amos Blomqvist’s LearnHarness. I added a topic picker that drafts a real teaching session.” |
| 0:40–1:25 | Choose Markov chains and edit the prompt | “The prompt is editable. Pressing Send uses the same model readiness checks and Teach pipeline as any typed topic.” |
| 1:25–2:35 | Submit and answer the first prompt if a provider is ready | “The server owns the agent turn. The browser renders live events and can reopen the saved record.” |
| 2:35–3:20 | Sidebar and graph | “The sidebar reopens prior sessions. The graph builds from extracted propositions and reasoning chains, so it can start empty.” |
| 3:20–4:00 | Settings and repository attribution | “Model connections are configurable. The agent, storage and Electron architecture come from LearnHarness. The customized source is AGPL-3.0-only.” |

## Rehearsal and fallback

Start the local dev server before presenting. Check Settings for a usable provider and Strong, Cheap, and Vision model selections. Use a disposable profile and an innocuous demo topic. If possible, create one real session before the demo and reopen it during rehearsal.

If credentials or network access are unavailable, show Quick Start filling the composer, show the existing setup gate, and browse any real previously saved session. Identify it as a saved session. If none exists, show the empty graph and use the architecture trace to explain the live path. Use browser mode if the Electron installer or dev shell is unavailable. Verify the local server and browser are already working before relying on this fallback.
